Qdrant Collection Contextual Understanding
------------------------------------------

Qdrant collections are named sets of vector points with payload metadata. For this project, use one primary collection with payload-based partitioning unless hard isolation is required. The compatible design is:

- Collection: ontology_events
- Dense vector: semantic_event_vector
- Distance: Euclid, matching the current hybrid-vector direction.
- Sparse vector: lexical_event_vector for keyword/symbol matching.
- Payload partition keys: tenantId, landscapeRef, ontologyMode, axiomRef, targetNode, submittedBy, status.
- Raw JSON-LD must remain in payload metadata so deterministic validation and exact filtering do not depend on embeddings.
- Qdrant is not the source of truth for conformance. SHACL validation happens before ingestion.
- The immutable ledger remains the source of audit sequencing; Qdrant is retrieval acceleration.
